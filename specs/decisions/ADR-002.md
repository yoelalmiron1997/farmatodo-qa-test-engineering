# ADR-002 — Pytest como runner

**Estado:** aceptada · **Fecha:** 2026-10-23

## Contexto
Se necesitan fixtures con alcance controlado, parametrización legible, hooks para recolectar cada intento y un ecosistema de reintentos.

## Decisión
Pytest 8 con `pytest-rerunfailures` (reintentos), `pytest-randomly` (orden aleatorio), `pytest-socket` (sin red en unit) y un plugin propio de recolección.

## Alternativas consideradas
unittest (sin fixtures por alcance ni parametrización nativa) · behave/Gherkin (agrega una capa de traducción sin beneficio: la especificación ya vive en Markdown + YAML).

## Consecuencias
El plugin propio depende de hooks estables de pytest (`pytest_runtest_makereport`, `pytest_runtest_logreport`); se prueba con `pytester` (TC-FW-010).
