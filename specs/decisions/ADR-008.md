# ADR-008 — Flaky: rerunfailures + clasificador propio + análisis histórico

**Estado:** aceptada · **Fecha:** 2026-10-23

## Contexto
Reintentar sin registrar oculta la inestabilidad.

## Decisión
`pytest-rerunfailures` (2 reintentos, configurable con `QA_RERUNS`, 0 los desactiva) solo en E2E. El plugin registra cada intento; el clasificador distingue PASS limpio, FLAKY, FAIL, SKIPPED, BLOCKED y NOT RUN; el análisis histórico calcula estabilidad, flip rate y flaky sospechado sobre corridas comparables. El gate bloquea FLAKY P0.

## Alternativas consideradas
`flaky` o `pytest-retry` (incompatibles entre sí y con rerunfailures) · reintentar a nivel de job (pierde el detalle por intento).

## Consecuencias
Un timeout que termina fallando es FAIL, nunca FLAKY. Los unit tests no se reintentan nunca.
